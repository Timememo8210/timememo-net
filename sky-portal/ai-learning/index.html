TokenToken基础表示 模型真正读写的最小文本片段。像把句子切成积木块。文本分词后的离散单元。输入、输出、训练、计费影响上下文长度和推理成本。不一定等于一个汉字或一个英文单词。已深入
EmbeddingEmbedding基础表示 把文字、图片或声音变成一串数字坐标。像给每段内容分配一个语义地址。高维向量表示。检索、多模态、RAG需要向量化模型和存储。向量接近不等于事实完全相同。已深入
向量相似度Vector Similarity基础表示 比较两个向量在语义空间里靠不靠近。像看两个地址在地图上离多远。点积、余弦相似度、欧氏距离。搜索、去重、推荐、RAG向量库、ANN 索引、批量计算。比较的是语义相近，不是绝对一致。已深入
TransformerTransformer模型结构 现代大语言模型最核心的神经网络架构之一。像一套能并行阅读上下文的理解机器。主要依靠 Attention，而非循环网络。模型骨架矩阵计算密集，适合 GPU/TPU。Transformer 不是一个具体模型名。已深入
AttentionAttention模型结构 让模型决定当前 token 应该重点看哪些上下文。像读文章时把注意力放在关键句上。Query、Key、Value 的相似度加权。理解上下文长上下文会增加计算和显存压力。不是人类意识，只是权重分配机制。已深入
预训练Pretraining训练流程 用海量数据训练出“有底子”的基座模型。像先读完整个图书馆。通常做 next-token prediction 等自监督学习。大模型训练主阶段最吃数据、GPU/TPU、HBM、网络通信。不是把互联网可靠地背成数据库。已深入
后训练Post-training训练流程 把基座模型调成更会对话、更安全的助手。像博学的人进岗位培训。SFT、偏好对齐、安全调优、工具使用训练。预训练之后数据少得多但质量要求高。不等于 RLHF，也不只是改语气。已深入
监督微调SFT训练流程 用“问题 + 理想答案”教模型模仿好回答。像老师给学生看标准答案。用监督学习继续训练模型输出。后训练早期常见步骤高质量标注数据比数量更关键。SFT 不等于完整后训练。已深入
蒸馏Knowledge Distillation训练流程 让小模型模仿大模型或教师模型的能力和行为。像优秀老师把解题思路和风格教给学生。用教师模型的 logits、概率分布、生成答案或推理轨迹训练学生模型。模型压缩、能力迁移、部署前优化比从零预训练省，但会消耗教师生成数据和学生训练成本。不是复制参数，也不是保证无损压缩。已深入
奖励模型Reward Model对齐评估 学习给多个回答打分，判断哪个更符合偏好。像训练一个评分老师。用人类排序数据训练偏好打分器。经典 RLHF 中间环节需要成对或排序偏好数据。评分高不等于事实一定正确。已深入
RLHFRLHF对齐评估 用人类偏好和强化学习让回答更符合产品目标。像按老师评分反复改作文。常见流程是 SFT → RM → PPO。后训练偏好对齐工程复杂，显存和采样成本高于普通 SFT。不能保证模型永远真实或安全。已深入
DPODPO对齐评估 直接用“好答案 vs 差答案”优化模型偏好。像直接告诉学生 A 比 B 好。不显式训练 reward model，不跑 PPO 式 RL。后训练偏好对齐仍需要高质量偏好数据和参考模型。不是没有人类反馈，也不是总优于 RLHF。已深入
评测Evaluation对齐评估 判断模型有没有变强、哪里危险、能不能发布。像考试、路考和压力测试。benchmark、人工偏好、红队、安全测试。训练后和发布前多为推理负载，也会消耗大量 GPU 时间。单个榜单不能代表真实能力。已深入
GPU / TPUGPU / TPU硬件部署 加速大规模矩阵和张量计算的主要硬件。像一整排专做矩阵乘法的流水线。GPU 更通用，TPU 是 Google 的 ML 专用 ASIC。训练和推理看算力、显存、HBM、互联、生态和成本。不是芯片越多就一定训练越快。已深入
推理Inference硬件部署 训练完成后，模型实际生成答案的过程。像考试时现场作答。前向计算，常分 prefill 和 decode。部署服务阶段关注延迟、吞吐、KV cache、显存和带宽。推理也可能很贵，尤其是高并发长上下文。已深入
RAGRAG知识增强 先检索资料，再让模型基于资料回答。像开卷考试，先翻资料再作答。检索器 + 生成模型的组合。应用层增强向量库、索引、重排序、引用管理。RAG 不能自动保证资料正确。已深入
扩散模型Diffusion Model生成模型 从噪声一步步去噪生成图片、视频或音频。像从雪花噪点里慢慢画出图像。学习正向加噪和反向去噪过程。生成式 AI训练和采样都算力密集。不是从图库里复制一张图。已深入
世界模型World Model模型结构 学习世界状态如何随动作变化。像在脑子里模拟下一步会发生什么。环境的压缩空间和时间表示。Agent、机器人、规划需要环境交互数据或仿真数据。不等于大语言模型拥有完整现实理解。已深入

Token v1.0

模型真正读写和计费的最小片段，通常不是一个完整词，也不一定是一个汉字。

一句话

Token 是文本进入模型前被切成的小单位；模型先看到 token ID，再把它变成向量参与计算。

人话比喻

像把一段话拆成乐高块。模型不是直接读“整篇文章”，而是按块接收、理解和生成。

技术定义

Tokenizer 把字符串切成 token，并映射到词表里的 ID。常见方法包括 BPE、WordPiece、Unigram 和 SentencePiece。

作用

决定上下文长度、截断风险、输入输出成本、推理延迟，以及模型能否稳妥处理生僻词、代码、Emoji 和多语言文本。

常见方法

子词分词、字节级分词、特殊 token 标记开始/结束/分隔/填充；不同模型的 tokenizer 结果可能不同。

资源要求

token 越多，训练和推理中的注意力计算、KV cache、延迟和费用通常越高；长文本还可能被截断。

常见误区

Token 不等于英文单词，也不等于中文字符。同一句话在不同模型或不同 tokenizer 下 token 数可能不同。

复习问题

  • 为什么同一句话在不同模型里 token 数会不同？
  • 为什么 token 数会影响成本和延迟？

相关概念

Tokenizer、BPE、SentencePiece、Context Window、KV cache、Embedding。

Embedding v1.0

把文本、图片或音频表示成向量，让模型可以计算语义接近程度。

一句话

Embedding 是内容的数字坐标：相似内容在向量空间里通常更靠近。

人话比喻

像给每段文字、每张图片发一个“语义地址”。地址近，说明它们在模型眼里可能谈的是相近的事。

技术定义

Embedding 是稠密向量表示。Token embedding 是 token ID 到向量的映射；文本 embedding 通常表示句子、段落或文档。

作用

支撑语义搜索、推荐、聚类、去重、RAG 检索、多模态对齐和相似内容发现。

常见方法

词向量、句向量、对比学习、多模态 embedding；实际应用中还要做分块、清洗、元数据和版本管理。

资源要求

需要 embedding 模型、批量向量化、向量存储和索引。大规模检索还要关注维度、召回率、延迟和重建索引成本。

常见误区

向量接近不等于事实相同。Embedding 表示统计或语义相关性，不保证来源可靠、事实正确或完全同义。

复习问题

  • 为什么不同 embedding 模型的向量不应混在一起比较？
  • 为什么 embedding 不能当作原文的无损压缩？

相关概念

向量相似度、RAG、CLIP、对比学习、向量数据库、重排序。

向量相似度 Vector Similarity v1.0

比较两个向量在语义空间里的接近程度，常用于检索、推荐和去重。

一句话

向量相似度不是比较原文，而是比较内容被模型表示成向量后的方向、距离或内积。

人话比喻

像在地图上看两个地址离多远。离得近通常说明相关，但不能证明它们是同一个地方。

技术定义

常见指标包括余弦相似度、点积/内积、L2 欧氏距离。归一化后，点积和余弦相似度排序常会接近。

作用

从大量候选中找最相关的文本、图片、商品、用户或代码片段，是 RAG 和向量数据库的基本检索动作。

常见方法

精确最近邻适合小规模；ANN 近似最近邻用索引、量化和分桶换取速度与内存效率。

资源要求

规模越大越依赖向量索引、内存、磁盘、批量计算和重排。指标必须和 embedding 模型及索引配置匹配。

常见误区

相似度分数不是概率。“0.8 相似”不等于“80% 正确”，也不代表事实一致。

复习问题

  • 余弦相似度和点积主要差别是什么？
  • 为什么 ANN 检索可能漏掉真正最近的向量？

相关概念

Embedding、向量数据库、ANN、Faiss、RAG、rerank。

Transformer v1.0

现代大模型的主流神经网络骨架，用注意力机制并行处理上下文。

一句话

Transformer 是一种模型架构，不是某个模型名；GPT、BERT、T5 等都可以看作 Transformer 家族的不同用法。

人话比喻

像一个能同时翻看整段上下文的阅读团队，每层都重新决定哪些信息该互相参考。

技术定义

原始 Transformer 由 encoder-decoder 组成，核心模块包括 self-attention、前馈网络、残差连接、归一化和位置表示。

作用

解决 RNN 顺序处理难并行的问题，让大规模训练更适合 GPU/TPU，并成为语言、视觉、语音和多模态模型的基础架构之一。

常见变体

GPT 常用 decoder-only；BERT 常用 encoder-only；T5 等使用 encoder-decoder；MoE 则把部分前馈层换成专家路由。

资源要求

矩阵乘法密集，适合加速器。标准 self-attention 对序列长度通常有二次复杂度压力，长上下文会明显增加显存和算力需求。

常见误区

Transformer 不等于 Attention。Attention 是核心部件，但前馈网络、位置编码、残差和归一化同样重要。

复习问题

  • 为什么 Transformer 比 RNN 更适合大规模并行训练？
  • 为什么 Transformer 需要位置信息？

相关概念

Attention、位置编码、MLP、残差连接、LayerNorm、MoE、长上下文。

Attention v1.0

让每个 token 根据 Query、Key、Value 决定该参考哪些上下文信息。

一句话

Attention 是一种可微的信息路由机制：当前 token 通过权重加权其他 token 的 value。

人话比喻

像读一句话时临时划重点。不同问题会让你把注意力放到不同词上，而不是平均看每个词。

技术定义

常见 scaled dot-product attention 用 Query 和 Key 的相似度做 softmax 权重，再对 Value 加权求和。

作用

让模型建立长距离依赖、代词指代、代码变量引用、上下文条件和跨模态对齐。

常见方法

Self-attention 的 Q/K/V 来自同一序列；cross-attention 让一个序列参考另一个序列；multi-head attention 并行关注不同表示子空间。

资源要求

注意力矩阵会随上下文长度增长而变重。FlashAttention 等方法通过减少 HBM 读写来提升效率。

常见误区

Attention 权重不是人类意识，也不是严格因果解释。最终输出还受多层 MLP、残差、归一化和采样影响。

复习问题

  • Query、Key、Value 分别像什么？
  • 为什么自回归模型需要 causal mask？

相关概念

Transformer、Q/K/V、Multi-head Attention、Causal Mask、KV cache、FlashAttention。

预训练 Pretraining v1.0 已公开事实 + 业界常见做法

用海量数据训练基座模型，主要形成语言、知识关联、代码模式和通用能力。

一句话

预训练是在造“底子”：模型通过海量文本、代码或多模态数据，学习怎么根据上下文预测下一个 token。

人话比喻

像一个人先读图书馆、网页、代码库和教材。它还没学会怎么当客服或老师，但已经有了语言和知识底盘。

技术定义

通常是自监督学习，不需要人工逐条写标准答案；语言模型最典型目标是 next-token prediction。

作用

很大程度上决定模型的基础能力底盘和上限：语言结构、常识关联、代码模式、推理雏形和跨领域泛化。

常见方法

Causal LM、混合精度训练、数据/张量/流水线并行，配合大规模数据清洗、去重和数据配比。

资源要求

通常是最耗数据和算力的阶段；瓶颈不只是 GPU/TPU 数量，还包括 HBM 显存与带宽、互联通信、存储吞吐和故障恢复。

输出是什么

一个基座模型。它会续写、补全和泛化，但还不一定稳定听指令，也不一定符合产品安全边界。

常见误区

预训练不是“把互联网变成可靠数据库”。模型学到的是统计规律和关联，可能记错、混淆、过时或编造。

复习问题

  • 为什么预训练通常比后训练更耗算力？
  • 为什么说基座模型有知识，但还不一定好用？

相关概念

Token、Transformer、Attention、Scaling Law、GPU/TPU、后训练。

后训练 Post-training v1.0 业界常见做法

预训练之后的一组行为塑形流程，把基座模型调成更会和人协作的助手。

一句话

后训练不是重新从零训练，而是让已有能力更符合人的使用方式：听指令、会解释、懂边界、少乱答。

人话比喻

预训练像读书多年，后训练像上岗培训。同一个人有知识，但还要学会怎么回答客户、怎么拒绝危险请求。

技术定义

后训练是预训练之后的统称，可能包含 SFT、RLHF、DPO、拒绝采样、安全微调、工具调用训练和专项能力增强。

作用

改善指令遵循、多轮对话、回答结构、帮助性、安全性、工具使用和产品体验。

常见方法

监督微调、偏好对齐、红队数据回灌、安全拒答训练、代码或工具使用专项数据训练。

资源要求

计算量通常远小于预训练，但数据质量要求更高；少量高质量样本也可能明显改变模型风格和行为。

输出是什么

一个更适合聊天、办公、编程或工具调用的模型；部署时还可能配合系统提示、过滤器和监控策略。

常见误区

后训练不等于 RLHF；后训练也不只是“改口气”。它更准确地说是在塑造行为、偏好和安全边界。

复习问题

  • 为什么后训练能让模型明显更好用？
  • 为什么不能把后训练简单理解成“补知识”？

相关概念

SFT、RLHF、DPO、Reward Model、Evaluation、Safety Tuning。

监督微调 SFT v1.0

用人工或高质量模型生成的“问题 + 理想答案”样本，让模型模仿好回答。

一句话

SFT 是后训练中最直观的一步：给模型看标准答案，让它学回答格式和表达方式。

人话比喻

像老师给学生一批范文和解题步骤：“遇到这种题，不要乱写，按这个结构答。”

技术核心

通常继续用监督学习和交叉熵损失训练，让模型在给定指令时输出示范答案。

资源要求

比预训练更依赖样本质量。小模型可用 LoRA/QLoRA 等低成本方式，大模型全量微调仍需要多卡高显存。

常见误区

SFT 不是知识库；它主要教“怎么答”，不能自动保证事实正确，也会继承或放大样本里的坏习惯。

相关概念

Instruction Tuning、LoRA、RLHF、DPO、数据标注。

蒸馏 Knowledge Distillation v1.0

用强模型当老师，把能力、答题风格或推理行为迁移给更小、更便宜或更专用的学生模型。

一句话

蒸馏就是让一个“学生模型”模仿“教师模型”，尽量学会教师的输出分布、答题风格、推理过程或专项能力。

人话比喻

不是把老师的大脑复制给学生，而是老师把解题思路、答案倾向、常见坑和表达风格浓缩成训练材料，让学生学完后做题更快、成本更低。

技术定义

经典知识蒸馏用教师模型的 soft targets 或 logits 训练学生模型；大语言模型里也常用教师生成的指令答案、推理轨迹、偏好样本或任务示范来训练学生。

作用

常用于模型压缩、能力迁移和部署优化：把大模型的部分能力迁到小模型、端侧模型、垂直领域模型或低延迟服务上。

常见方法

Logits 蒸馏、response distillation、feature distillation、sequence-level distillation、self-distillation，以及用教师模型生成 SFT 数据。

资源要求

通常比从零预训练省很多；主要成本在教师模型生成数据、学生模型训练、评测和反复筛选数据。如果教师很大或样本很多，生成成本仍然不低。

输出是什么

一个更小、更快、更便宜或更专用的学生模型。它可能在目标任务上接近教师，但不一定保留教师的全部能力。

常见误区

蒸馏不是直接复制权重，也不是保证无损压缩；学生模型可能继承教师的偏见和错误，蒸馏数据没覆盖到的能力也可能学不到。

复习问题

  • 为什么蒸馏能降低部署成本？
  • 蒸馏和 SFT 的区别是什么？
  • 为什么蒸馏不是无损压缩？

相关概念

SFT、Teacher Model、Student Model、Logits、Soft Targets、模型压缩、量化、剪枝、推理成本。

Reward Model / RLHF v1.0

用人类偏好训练“评分老师”，再用强化学习让模型更偏向高评分回答。

一句话

RLHF 是从人类反馈中学习：人先比较多个回答，模型再学会更常给出人类偏好的回答。

人话比喻

学生写几份作文，老师排序；再训练一个评分老师，学生之后按评分老师的偏好反复改作文。

经典流程

InstructGPT 的典型流程是 SFT → 训练 Reward Model → 用 PPO 做强化学习优化。

资源要求

需要偏好比较数据。PPO 式 RLHF 工程复杂，通常要生成样本、跑策略模型、参考模型、奖励模型和价值模型。

常见误区

RLHF 不是让模型掌握绝对真理；它让模型贴近标注者和产品定义的偏好，可能引入讨好、冗长或偏见。

相关概念

PPO、KL 约束、偏好数据、Reward Hacking、DPO。

DPO Direct Preference Optimization v1.0

直接用“被偏好的回答”和“不被偏好的回答”训练模型，流程比传统 PPO-RLHF 更简洁。

一句话

DPO 不单独训练显式奖励模型，而是把偏好对比直接写进模型优化目标。

人话比喻

不再先培养一个“评分老师”，而是直接告诉学生：这份答案比那份好，以后往这个方向写。

技术核心

用 chosen/rejected 成对偏好数据，并通常引入一个冻结的参考模型，控制新模型不要偏离太远。

资源要求

训练流程通常比 PPO-RLHF 轻，但仍需要高质量偏好数据、当前模型和参考模型的显存预算。

常见误区

DPO 不是“不需要反馈”。它仍然需要偏好数据，只是不用显式 reward model 和 PPO 式强化学习循环。

相关概念

RLHF、Preference Data、Reference Model、Alignment。

评测 Evaluation v1.0

用系统化测试判断模型或应用有没有真的变好，哪里会失败，能不能发布。

一句话

评测不是只跑排行榜，而是为具体任务定义成功标准、测试样本、评分方法和回归检查。

人话比喻

像考试、路考、体检和压力测试的组合。会做题不够，还要看真实路况、安全边界和长期稳定性。

技术定义

评测可以覆盖基础模型、提示词、RAG、工具调用和 Agent 流程，指标包括正确性、安全性、鲁棒性、延迟、成本、偏见和用户偏好。

作用

判断改动是否有效，发现失败模式，防止模型、提示词、索引或工具升级后出现回归。

常见方法

程序化规则、参考答案指标、人工评审、LLM-as-judge、成对偏好、红队测试，以及线上 A/B 或人工抽检。

资源要求

多为推理负载。高质量评测集、人工标注、失败样本管理和持续运行的 eval pipeline 往往比单次跑分更重要。

常见误区

公开榜单分数不等于产品质量。LLM 裁判也不是绝对真值，可能有位置偏差、冗长偏好、自我偏好和评分不稳定。

复习问题

  • 为什么评测要包含真实失败样本？
  • 为什么只看一个总分会误导产品决策？

相关概念

Benchmark、HELM、MT-Bench、红队、偏好评测、RAGAS、回归测试。

GPU / TPU v1.0

训练和推理常用的 AI 加速器，关键不只是峰值算力，还包括显存、带宽、互联和生态。

一句话

GPU 和 TPU 都擅长大规模张量计算，是现代深度学习训练和推理的核心硬件。

人话比喻

像一排专门做矩阵乘法的工厂机器。机器本身强不强重要，传送带、仓库、电力和调度也同样重要。

技术定义

NVIDIA GPU 有 SM、Tensor Core、缓存和 HBM；Google TPU 是面向机器学习的 ASIC，核心包括矩阵乘法单元和高速互联。

作用

加速模型训练、微调、批量推理、embedding 生成和大规模矩阵运算。

选择因素

看 FLOPS、HBM 容量、HBM 带宽、互联、框架支持、编译器、可获得性、成本、团队经验和云平台约束。

资源要求

大模型训练还需要并行策略、数据读取、checkpoint、网络通信和故障恢复。推理则更看显存容量、带宽、调度和利用率。

常见误区

不是 FLOPS 越高就一定越快，也不是卡越多就线性加速。通信、内存访问、kernel、batch 和数据管道都会限制实际速度。

复习问题

  • 为什么 HBM 带宽对推理很关键？
  • 为什么 TPU 不是“更强 GPU”这么简单？

相关概念

Tensor Core、MXU、HBM、NVLink、ICI、FSDP、ZeRO、混合精度。

推理 Inference v1.0

训练完成后实际生成答案的阶段，核心指标是延迟、吞吐、显存和服务稳定性。

一句话

推理是模型用已训练好的参数做前向计算，读输入并逐 token 生成输出。

人话比喻

训练像备考和改知识结构，推理像正式考试现场作答。不会改大脑参数，但会消耗时间、纸张和座位。

技术定义

LLM 推理通常分 prefill 和 decode：prefill 处理输入并建立 KV cache，decode 逐步生成输出 token。

作用

把模型能力变成用户可用的服务，支撑聊天、搜索、代码、Agent、批处理和实时流式响应。

常见方法

批处理、连续批处理、KV cache、prefix caching、量化、推理并行、PagedAttention、FlashAttention、speculative decoding。

资源要求

模型权重常驻显存；长上下文和高并发会让 KV cache 成为显存瓶颈。线上还要看 TTFT、TPOT/ITL、TPS、RPS 和 p95/p99。

常见误区

推理虽然通常不做反向传播，但不等于便宜。长上下文、多轮对话、高并发和流式输出会让显存和带宽压力很大。

复习问题

  • prefill 和 decode 分别在做什么？
  • 为什么高吞吐不一定代表低延迟？

相关概念

KV cache、TTFT、TPOT、continuous batching、PagedAttention、量化、SLA。

RAG Retrieval-Augmented Generation v1.0

先检索外部资料，再让模型基于资料回答，适合私有知识库和最新信息场景。

一句话

RAG 是“先找资料，再回答”：把模型参数里的知识和外部知识库结合起来。

人话比喻

像开卷考试。学生不是只凭记忆答题，而是先翻指定资料，再组织答案并给出处。

技术定义

典型流程是资料解析、切块、embedding、索引、检索、重排、上下文注入、生成、引用和评测。

作用

适合企业文档、私有资料、最新政策、产品说明和需要引用来源的问答，降低知识过期和无依据回答的风险。

常见方法

关键词搜索、向量搜索、混合检索、metadata filter、rerank、query rewrite、上下文压缩和基于证据的拒答。

资源要求

需要文档管道、向量库或搜索引擎、权限控制、索引更新、检索评测和生成评测。瓶颈常在资料质量而不是模型本身。

常见误区

RAG 不能自动消除幻觉。有向量数据库也不等于有好 RAG；检索不到、资料错、重排差或提示词弱都会失败。

复习问题

  • 为什么 RAG 要分开评测检索质量和回答质量？
  • 什么时候 RAG 比微调更合适？

相关概念

Embedding、向量相似度、DPR、rerank、RAGAS、引用、权限过滤。

扩散模型 Diffusion Model v1.0

学习从噪声一步步去噪生成数据，是图像、视频和音频生成的重要路线。

一句话

扩散模型先学习“怎么把数据加噪”，再学习“怎么从噪声还原数据”。生成时从噪声开始逐步去噪。

人话比喻

像先把清晰照片一点点弄成雪花噪点，再训练一个画师学会反过来从雪花里恢复图像。

技术定义

DDPM 把生成建模为潜变量过程；score-based 视角把它理解为学习噪声分布下的梯度方向。

作用

常用于文生图、图生图、视频、音频、编辑、超分辨率和条件生成。

常见方法

DDPM、DDIM、score-based SDE、classifier-free guidance、Latent Diffusion、采样器加速和蒸馏少步生成。

资源要求

训练和采样都算力密集。Latent Diffusion 在压缩后的 latent 空间去噪，再解码成像素，可显著降低高分辨率生成成本。

常见误区

扩散不是简单复制图库，也不是物理扩散模拟。guidance 或步数越高不一定越好，可能牺牲多样性或引入伪影。

复习问题

  • 为什么扩散模型生成通常从随机噪声开始？
  • Latent Diffusion 为什么比像素空间扩散更省？

相关概念

DDPM、DDIM、Score Matching、Latent Space、VAE、Classifier-Free Guidance、采样器。

世界模型 World Model v1.0

让智能体学习环境如何随动作变化，用来预测、规划和在想象中训练策略。

一句话

世界模型是智能体的内部预测器：如果我采取某个动作，环境接下来可能变成什么样？

人话比喻

像人在脑子里预演：“如果我往左打方向，车会怎样？”先模拟后行动，可以减少现实试错成本。

技术定义

它学习状态、动作、下一状态、奖励或观测之间的动态关系，常在压缩 latent 空间中预测未来。

作用

用于规划、机器人、游戏、自动驾驶、Agent 行为学习和 model-based reinforcement learning。

常见方法

VAE 压缩观测、RNN/Transformer 学动态、在想象轨迹中训练策略；Dreamer 系列用 latent dynamics 学习行为。

资源要求

需要环境交互数据、仿真数据或视频/动作数据。难点是长期预测、因果一致性、可控性和分布外泛化。

常见误区

世界模型不等于视频生成器，也不要求完美复刻现实。画面像真的不代表动态、因果和任务决策都正确。

复习问题

  • 为什么世界模型能减少真实环境试错？
  • 为什么世界模型和普通大语言模型的“知识”不是一回事？

相关概念

Agent、Model-Based RL、Planner、Latent Dynamics、Dreamer、机器人、仿真。

对比专题

先把最容易混的几组关系固定下来。

预训练 vs 后训练

预训练主要是建立基础能力，数据最大、算力最大，常用自监督目标。后训练主要是塑造可用性和行为边界，数据少得多但质量要求高。

SFT vs RLHF vs DPO

SFT看标准答案学习；RLHF先学评分再用强化学习优化；DPO直接用偏好对比优化。

蒸馏 vs SFT

SFT通常学人工或精选示范答案；蒸馏学教师模型的输出分布、答案、推理轨迹或行为风格，目标常是能力迁移和降低推理成本。

训练 vs 推理

训练要前向、反向、梯度和优化器状态；推理通常只做前向，但长上下文和高并发会让 KV cache、显存和延迟成为瓶颈。

GPU vs TPU

二者都能做大规模张量计算。GPU 生态更通用，TPU 是 Google 的机器学习专用 ASIC；适不适合取决于框架、互联、成本、可获得性和团队经验。

Token vs Embedding

Token是离散的文本片段和 ID；Embedding是连续向量。前者像积木块编号，后者像语义坐标。

Transformer vs Attention

Attention是信息路由机制；Transformer是包含 attention、MLP、残差、归一化和位置表示的完整架构。

RAG vs 微调

RAG适合接入可更新、可引用、私有资料；微调更适合改变行为、格式、风格或专项技能。二者可以组合，不是互斥。

评测 vs 排行榜

排行榜是公开任务上的一个信号；评测是围绕你的真实场景、失败样本、安全边界、成本和延迟建立的持续机制。

Prefill vs Decode

Prefill处理输入并建立 KV cache，常影响首 token 时间；decode逐 token 生成，常影响持续输出速度和显存带宽。

扩散 vs 自回归生成

扩散通常从噪声逐步去噪；自回归按顺序生成下一个 token。两者都能生成内容，但训练目标和采样过程不同。

硬件与算力：不要只看“用了多少卡”

大模型训练像一座大型工厂。芯片是核心机器，但仓库、传送带、电力、排程和故障恢复同样决定产能。

训练大模型通常使用 GPU 或 TPU 集群。关键瓶颈包括：模型权重、激活值、梯度、优化器状态占用的显存；HBM 带宽；GPU/TPU 之间的高速互联；数据读取和 checkpoint 存储；以及集群稳定性。闭源模型的参数量、训练硬件和训练成本如果没有官方披露，应标记为推测。
