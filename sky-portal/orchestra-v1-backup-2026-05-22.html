Orchestra
多模型 Agent 协同流水线 Orchestra
Multi-Model Agent Pipeline

一个让三种 AI 模型自动协同工作的编排系统。Opus 做架构规划，GLM 5.1 并行编码，Codex 审查质量——循环迭代直到代码通过审查。睡觉前启动，醒来收代码。 An orchestration system that coordinates three AI models automatically. Opus architects the plan, GLM 5.1 workers code in parallel, Codex reviews quality — looping until the code passes review. Start before bed, wake up to working code.

设计思路Design Philosophy

核心问题：Claude Code (Opus) 很强但很贵，GLM 5.1 便宜但需要指导，Codex 擅长审查但不擅长规划。如果能让它们各司其职、协同工作呢？ Core problem: Claude Code (Opus) is powerful but expensive, GLM 5.1 is cheap but needs guidance, Codex excels at review but not planning. What if they each did what they're best at?

Orchestra 的答案是一个三阶段循环流水线——不是框架，不需要额外依赖，就是一个 Python 脚本加一个 HTML 页面。简单到可以在 10 分钟内读完全部代码。 Orchestra's answer is a three-phase loop pipeline — not a framework, no extra dependencies, just a Python script and an HTML page. Simple enough to read all the code in 10 minutes.

GLM 5.1 ACP 接入GLM 5.1 ACP Integration

Worker 进程通过环境变量注入 ACP 配置，让 Claude Code CLI 透明切换到智谱 Z.AI 端点： Worker processes inject ACP config via environment variables, transparently switching Claude Code CLI to Zhipu Z.AI endpoint: 

# ACP 环境变量（Worker 进程自动注入）
ANTHROPIC_BASE_URL="https://api.z.ai/api/anthropic"
ANTHROPIC_DEFAULT_SONNET_MODEL="glm-5.1"
ANTHROPIC_DEFAULT_OPUS_MODEL="glm-5.1"
ANTHROPIC_DEFAULT_HAIKU_MODEL="glm-4.5-air"

Agent 间记忆共享Memory Sharing Between Agents

每个 Worker 是独立的 claude -p 进程，它们之间没有直接通信。共享上下文通过两种方式传递： Each worker is an independent claude -p process with no direct communication. Shared context flows through two channels:

  1. Prompt 注入 — Opus 规划时生成 shared_context 字段，编排脚本将其写入 .orchestra-context.md，所有 Worker 启动时读取Prompt injection — Opus generates a shared_context field during planning, written to .orchestra-context.md, read by all workers at startup
  2. 文件系统 — Worker 修改代码文件，Review 阶段通过 git diff 看到所有变更File system — Workers modify code files; the review phase sees all changes via git diff

关键设计决策Key Design Decisions

  • 不用框架 — 不依赖 CrewAI / LangGraph / AutoGen。200 行 Python + 400 行 HTML 就够了。引入框架只会增加学习成本和调试难度。No frameworks — No CrewAI / LangGraph / AutoGen. 200 lines Python + 400 lines HTML is enough. Frameworks add learning curves and debugging complexity.
  • 文件即总线 — Agent 间通过文件系统通信（.orchestra-context.md, state.json）。比消息队列简单，对 AI 编码 Agent 来说足够了。Files as message bus — Agents communicate via file system (.orchestra-context.md, state.json). Simpler than message queues, sufficient for AI coding agents.
  • 三模型混搭 — 不同阶段用不同提供商的不同模型。Anthropic (Opus), Z.AI/Zhipu (GLM), OpenAI (Codex)。取长补短。Multi-vendor model mixing — Different models from different providers for different phases. Anthropic (Opus), Z.AI/Zhipu (GLM), OpenAI (Codex). Best of each.
  • 优雅降级 — Codex 不可用时自动回退 Opus 审查。JSON 解析失败时有兜底逻辑。Worker 失败不阻塞其他 Worker。Graceful degradation — Falls back to Opus review if Codex unavailable. JSON parse failures have fallback logic. Worker failures don't block others.
