One clear loop from document to property history

The original is retained first. AI prepares a proposal, the user checks and edits it, and only a deliberate confirmation turns it into a property record.

01

Open the correct home

A permanent property ID keeps every record and original attached to the home.

02

Upload a photo or PDF

The original is stored before reading and remains available to authorised owners and administrators.

03

AI prepares a proposal

The reader extracts work, provider, date, cost and supporting evidence without silently inventing missing facts.

04

Review, edit or save a draft

Every visible field can be corrected. Incomplete work can be saved and resumed later.

05

Confirm the record

Confirmation writes a versioned record. Later corrections create another revision rather than erasing history.

06

Share the right view

Owners see their originals; contributors manage their own submissions; buyers see confirmed history only.

The interface responds differently to four document outcomes

Readable

A populated review form appears. The user edits anything that is wrong, reviews the summary and confirms.

Partial

Known fields are kept; missing values remain blank. The user completes only what can be verified.

Unreadable or reader failure

The original stays attached. The user can retry, choose another document or enter the details manually.

Unrelated image

No maintenance record is created automatically. The user can replace it or intentionally enter details by hand.

A compact output built for a home's service history

Unknown values remain null. Source evidence is retained for review, while provider request identifiers and platform cost are removed from property-facing responses.

Access follows the property and the person’s role

Application

Two layers of access

The partner preview first requires an invited account. Inside Domic, administrators use a management code and each property link carries an owner, contributor or buyer role.

Storage

Originals and records stay separate

Original files are retained in private object storage. Structured records, versions, access grants and audit events are kept in the database. The public TimeMemo page stores neither.
