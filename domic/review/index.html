The product loop

The original is saved before a record is confirmed

AI proposes; the user decides. A failed reading never silently becomes a maintenance fact, and an incomplete review can be saved as a draft.

  1. Open homeProperty-scoped link
  2. UploadPDF or image
  3. Store originalPrivate object storage
  4. ReadStructured proposal
  5. ReviewEdit or save draft
  6. ConfirmVersioned history

Step 0 · Protection

Two gates protect the preview and its management tools

The host first checks the invited account. Domic then applies its own administrator code or property-scoped owner, contributor and buyer capabilities.

Step 1 · Property setup

Create one permanent identity for the home

Records belong to a property, not to a loose pile of user uploads. The administrator creates the home, assigns the first owner label and issues role-specific links.

Design decision: The home is the durable subject. Users receive roles around it, so the maintenance history can survive a change of owner.

Steps 2–6 · Normal receipt flow

Every extracted field remains editable before confirmation

This path uses a synthetic UK PDF. The reader supplies a structured proposal, the user corrects it, saves a draft, reopens it and confirms a summary.

Recovery behaviour

Three failure cases produce three clear next steps

In each case, the original has already been stored. No confirmed maintenance record is created until a person supplies or approves usable facts.

Partial results follow the same rule. Verified fields are shown; unknown fields stay blank. A person fills only what can be supported by the document or their own knowledge.

Fixed output contract

A compact record for the life of a home

Receipts vary widely, so the schema stays stable while values may be absent. Evidence and the original support review; human confirmation decides whether the proposal becomes history.

Roles and storage

Visibility is deliberate at every layer

Current engineering status

Verified in this build

  • 84 of 84 automated tests pass.
  • The production build completes successfully.
  • Anonymous requests to the hosted preview are blocked with HTTP 401.
  • Upload, editable review, draft, reopen, confirmation and the three recovery dialogs were exercised with synthetic files.

Required before open beta

These are known review findings, so this release is described as a protected partner preview rather than an open public beta.
