One home, clearly separated permissions

The property UUID and passport ID stay unchanged when its name, address or owner label is corrected. Access is tied to that home. A contributor or buyer link cannot be used to open a different property.

There is no Domic account login or registration in this release. A private property link carries that link’s permissions; the separate admin management code unlocks administration. Display names and owner labels are not verified identities or proof of ownership.

Treat each access link as a secret. Revocation blocks subsequent access, but cannot recall material someone has already viewed or copied.

An original first. A reviewed record next.

R2

Private original documents

Uploaded images and PDFs are retained in private cloud object storage. The backend checks file type and size, calculates the SHA256 hash and links the file to its property. There is no anonymous original-file URL.

D1

Records, permissions and revisions

Property IDs, structured records, access grants, versions, usage and audit events live in the cloud database. Browser storage is not the source of truth for the product’s records.

  1. Open the correct property

    Use the private link issued for the home. The server determines your role and property scope.

  2. Upload and retain the original

    Choose a supported image or PDF. The original is stored before extraction. A repeated upload to the same home is detected.

  3. Read with AI, or enter details manually

    AI returns a proposal. An unreadable, unrelated or failed response leaves the original available to the owner/admin, with retry or manual review available.

  4. Edit, then explicitly confirm

    Save an unfinished draft or check the confirmation box to save a confirmed version. “Confirmed” means a person reviewed this version; it is not an authenticity certificate or admin approval.

If two people edit the same version, the second save receives a version conflict. Reload the latest record and reconcile the changes; the service does not silently overwrite the other person’s work. Re-running AI also does not overwrite an already confirmed record.

AI settings: save, test, activate

Only the administrator can change provider settings. A saved draft does not replace the active configuration. API keys stay on the server; the dashboard shows only a masked hint.

  1. Save a configuration draft

    Choose the provider, supported endpoint and model. Supply a new key when changing provider or endpoint; the existing key is never silently forwarded to a different host.

  2. Test this exact draft

    Run the fixed synthetic receipt PNG through the extraction flow and check the expected GBP 264 result. A real provider test may incur a small charge. This checks the configuration, not accuracy on every receipt.

  3. Activate only after a successful test

    Activation applies to the same tested draft. A new draft needs its own test. Failed requests do not trigger automatic provider or model failover.

6 MiB

Maximum file size: 6,291,456 bytes. JPG, PNG, WebP and PDF are accepted; model PDF support is checked separately.

100 attempts / day

Default service-wide limit per UTC day. Pending and failed provider attempts, including configuration tests, count toward the limit. Deployment settings may change it.

Gemini 3.1 Flash Lite

Default model through OpenRouter. The administrator may select another tested configuration; this is not a fixed price or accuracy guarantee.

Native PDF support is limited to the previously verified OpenRouter default-model path. A successful PNG test does not prove PDF support for an arbitrary new model. Generic OpenAI-compatible configurations are image-only until specifically verified.
