# 文件录入、核对与失败恢复

更新于 2026 年 9 月 9 日。本文说明当前原型和下一阶段边界。真实实验结果另见测试报告；下方验收清单是计划，不代表全部已测试通过。

## 当前实现

Domic Home Passport 使用自行托管的 Tesseract.js 7.0.0，在浏览器本地读取英文印刷图片，再用有限的标签规则整理草稿字段。文件不会发送给外部识别服务。处理可取消、重试，最长等待 45 秒。PDF 当前提供预览和手工填写。Gemini、阿拉伯语识别及通用版式理解留待下一阶段。

若没有读出可用文字，本地 OCR 无法可靠区分清晰的普通照片与模糊单据，也不能仅因缺少关键词就断言文件无关。OCR 置信度只是引擎诊断值，不是某个字段正确的概率。

## 结果状态

| 结果 | 界面与下一步 |
|---|---|
| `review` | 找到可用房屋服务字段，自动打开可核对的摘要。 |
| `partial` | 保留已读信息、标出缺失项并打开核对；未知字段留空。 |
| `no_text` | 提示未找到可用票据信息，可能与照片内容、清晰度或语言有关；可换文件或手工填写，不断言照片模糊。 |
| `unrelated` | 文字线索提示其他服务，显示恢复选项，不自动写入房屋历史。 |
| `uncertain` | 无法确定相关性，请用户核对与房屋的关系或手工填写。 |
| 文件无效／不支持 | 说明实际格式、大小或解码问题，可重新选择。 |
| 取消／失败／超时 | 停止处理，可重试或手填；过期结果不能覆盖后来选择的文件。 |
| 重复文件 | 打开已有记录，避免重复创建。 |
| 保存失败 | 保留修改，提供重试或导出；不显示保存成功。 |

“能否读清”和“是否相关”分开记录。这些是保守的文字规则分流，不代表已具备可靠的图像分类或通用语义判断。

## 确认后才录入

选择文件 → 读取 → 自动显示摘要 → 必要时返回完整表格修改 → 查看最终摘要 → 勾选确认 → 保存。识别结束不等于归档成功，最终摘要必须反映最新修改。

核对内容包括房屋、做了什么、变更类型、具体位置、实际服务日期、公司、实际施工者、金额／币种、付款与完工状态。确认时需要归属房屋和有意义的服务描述；其余信息可保留未知并明确展示。用户可保存草稿，也可明确确认一份仍有缺项的记录。只有本地写入成功后才显示“已保存”。

Schema 1.1 将 `provider.organization_name` 与 `provider.person_name` 分开，保留 `provider.name` 兼容旧显示名称。`service.change_type` 表示维修、更换、安装、改善、维护或检查。缺失事实用 `null` 或 `unknown`，不编造日期、人物、币种或完工状态。导出保留原文证据、OCR 文字和引擎置信度；用户修改的信息不能冒充单据提取结果。

记录与原件存于当前浏览器 IndexedDB，尚不是共享数据库或跨设备账户。

## 身份与正式版后续工作

公司和实际施工者是不同身份。客户、制单人、销售人员或单独签名都不能证明是谁施工。未来匹配实体时保留原始名称与证据，同名不能自动合并公司或个人。

正式后端需要验证账户，分别处理房主与 Pro 对每处房屋的访问权限，保存识别、人工修改和访问审计记录，并防止重复提交。公司／个人匹配及联系信息连接必须有经过授权、可核对的决定。房屋地址不公开；上传票据不能自动发布地址或联系其中的人。投入实际使用前还需要阿拉伯语／混合语言样本、认证存储和服务端模型校验。

## 验收计划——结果另行记录

| 用例 | 计划验证 |
|---|---|
| 01–04 | 清晰票据、缺失字段、裁切后部分可读、严重模糊。 |
| 05–08 | 清晰普通照片、汽车服务账单、餐饮收据、房屋损坏照片。 |
| 09–12 | 陌生版式、客户／制单人／技师区分、有公司无施工者、报价单。 |

| 21–24 | 必填与可选缺项、存储失败、阿拉伯语／混合文字、更换文件或切换语言时未保存修改。 |
