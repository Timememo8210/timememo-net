# Domic Home Passport：伙伴交接与下一轮实现

本轮确认（2026-09-09）：用户选择先做可评审原型与方案，下一轮接真实 AI。产品名称已由用户确认为 Domic Home Passport。原型与项目说明采用英文默认、中文可切换。

## 已交付的独立模块

| 文件 | 职责 |
|---|---|
| index.html / styles.css | 中文工作台、原件/字段双栏、移动端单栏、确认弹窗 |
| app.js | 上传与预览、示例流程、人工编辑、状态切换、确认、历史、导出 |
| core.js | 空值/日期/金额校验、业务状态规则、文件校验与 hash、统一结构 |
| storage.js | 浏览器 IndexedDB 记录与原件事务保存、读取与删除 |
| samples.js / samples/*.json | 三组虚构示例及固定输出 |
| docs/receipt.schema.json | 本轮输出机器契约 |
| docs/extraction-prompt.md | 下一轮提取提示词草案，尚未实测 |
| docs/model-research.md | 当前官方模型能力、价格、成本假设与测评方法 |
| docs/reference-research.md | GitHub 参考与后续生产扩展候选 |
| docs/project-history.md | 旧项目依据及已有成果边界 |
| tests/ | 业务校验与流程验证 |

当前继承 TimeMemo 的静态 GitHub Pages 发布方式。没有模型请求、服务器上传、云数据库、登录、账户权限或跨设备同步。IndexedDB 是明确的设备本地原型存储，不是已接入 Domic 后端。原型没有第三方运行时代码，网页字体由 Google Fonts 加载，系统字体作为回退。

原始文件和结构化记录均存本浏览器 origin 下的 IndexedDB。任何同 origin 的应用代码都可能访问本地数据，这不是敏感资料隔离边界；公开评审以虚构样本为主。关闭标签后本地保存的记录可恢复；无痕模式、清理站点数据、浏览器逐出会丢失。JSON 导出不包含二进制原件，应分别下载原件。本轮没有 JSON 导入功能。

## 下一轮架构

延续旧计划：Next.js 应用 / API + Supabase PostgreSQL + 私有 R2 对象存储（若伙伴现有平台不同，用同一契约适配）。不在浏览器嵌入 API key，不让用户配置密钥。

```
桌面/手机浏览器
  → 受鉴权的上传接口 / 私有短时上传 URL
  → documents + extraction_jobs
  → 单一提取服务（Gemini adapter → schema → 业务规则）
  → 待审核草稿与字段证据
  → 用户核对与修改
  → 事务确认（记录 + 修订 + 文件关系）
  → 房屋活动历史 / 搜索 / 导出
```

不需要让多个 Agent 同时处理每张 receipt：一个可替换的多模态提取服务加确定性校验，更方便控制成本。多 Agent 用在这次研究与工程复核即可。

数据对象建议：`properties`（归属/权限），`documents`（单据性质、原件、hash、总金额），`activities`（房屋服务事件），`activity_documents`（多对多关联），`extraction_jobs`（运行状态/用量），`extractions`（模型原输出），`review_revisions`（用户修订/确认）。物业权限由服务端检查。单据总金额只保存一处，多个活动不可各复制全额作为支出。

## 接口草案（未部署）

| 接口 | 输入与输出 | 核心约束 |
|---|---|---|
| POST /api/documents | 文件 metadata + property_id → document_id + upload URL | 检查授权、实际文件类型、大小、配额；idempotency key |
| POST /api/documents/:id/extractions | document_id + schema_version → job_id | 只处理已上传且属于当前账户的文件；幂等；有限重试 |
| GET /api/jobs/:id | queued / processing / needs_review / failed / canceled | 输出进度阶段、错误原因、draft；只在确实可测时显示百分比 |
| PATCH /api/records/:id | 修改内容 + revision | 保存草稿；乐观锁，防止覆盖他人编辑 |
| POST /api/records/:id/confirm | 最终字段 + expected_revision + idempotency key | 权限与 schema/业务检查后事务确认，响应持久化成功才报成功 |
| GET /api/properties/:id/history | 筛选 / 分页 → 已确认活动 | 报价、凭证、完工状态分别显示 |
| DELETE /api/records/:id | record_id | 授权与用户确认；原件、派生数据和修订按保留政策删除 |

这里只是对接草案，不声称 Daniel 现有系统已有这些接口。

## 完整交互与失败处理

| 阶段 | 下一步或错误时应发生什么 | 本轮状态 |
|---|---|---|
| 选择文件 | PDF/JPG/PNG/WebP；本轮 15 MB；HEIC 提示转换；空文件/扩展名伪装拒绝 | 已实现基本类型、签名、大小检查；不是安全扫描/完整 PDF 解析 |
| 预览 | 原件始终可查看；PDF 无法嵌入则打开原件；跨页查看由浏览器 PDF 阅读器负责 | 已实现；加密/损坏 PDF 需要用户重新导出，未自动解析页数 |
| 上传 | 真实传输进度、网络中断保留任务/草稿、可重试 | 本轮不上传服务器；下一轮 |
| 识别 | 阶段提示，可取消；建议15秒后解释耗时，45秒超时并恢复；429/503带抖动退避至多一次 | 本轮仅示例延时流程与取消；下一轮真实任务 |
| 多文档 | 检测多张发票转拆分审核，长PDF明确页数和失败页，不能只读第一页 | 本轮人工拆分；下一轮检测 |
| 核对 | 未知/歧义明确提示；服务/开票日期分开；地址不匹配需用户确认归属 | 本轮手工归属；下一轮账户物业候选匹配 |
| 确认 | 确认弹窗 + 核对勾选；缺失允许，但房屋与摘要必需 | 已实现 |
| 保存 | 原件和字段同一事务；空间不足仍保留表单、提供草稿导出 | 已实现本地；服务端原子提交下一轮 |
| 去重 | 同文件打开现有记录；疑似重复让用户比对 | 同浏览器 SHA-256 已实现；跨设备/语义去重下一轮 |
| 重新编辑 | 不静默丢修改；返回修改可清空字段并保留 null；再次确认更新同记录 | 已实现；多人编辑和审计下一轮 |
| 成功 | 提示实际存储位置；历史可查看修改、JSON导出、原件下载、确认删除 | 已实现本地 |

原型没有自动核对明细加总，因为税、折扣、费用可能不齐。下一轮只在组成项完整时做差异提示，绝不擅自重写单据总额。

## 一周试点建议

1. Daniel 确认产品名、现有技术栈、鉴权方式、property_id、目标用户地区与业务范围。
2. 准备约 100 份经授权/合成、包含不同供应商与格式的样本；人工标注关键字段。旧13份PDF多数空白模板，只用于回归。
3. 接同一 schema 与 prompt，比较 2.5 Flash-Lite / 3.1 Flash-Lite / 3.5 Flash-Lite；2.5 Flash、3 Flash Preview 可作复杂样本对照。
4. 记录字段正确率、关键字段编造率、用户修改率、p50/p95、超时/重试率、每确认记录总成本；保留一组未用于调提示词的测试集。
5. 确认模型后补上传任务、私有原件、物业授权、事务保存与错误恢复，才进入小范围真实用户试用。

目标建议（未测得）：清晰单页 p50 <5秒 / p95 <15秒；关键字段金额、币种、日期等分开验收；任何模型建议先人审。合格门槛需根据伙伴实际样本共同确定。

## 本轮语言更新

工作台和说明页默认英文，提供中文切换。名称统一 Domic Home Passport。用户填写的姓名、地址、备注和原文证据不自动翻译；两种界面的输出字段名与枚举一致，导出的系统提示统一英文。保留现有浏览器存储与访问地址。面向用户所述阿拉伯地区受众，下一轮需按首发国家验证阿拉伯文票据、日期格式和当地币种；本轮尚未实现或实测阿拉伯文识别。
